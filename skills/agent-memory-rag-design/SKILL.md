# 智能体记忆系统与 RAG 设计

## R — 原理锚点

> 记忆四层架构由基础设施层 / Memory 类型层（Working·Episodic·Semantic·Perceptual）/ 存储层（Qdrant·Neo4j·SQLite）/ 嵌入层组成；按生命周期与抽象度选记忆类型（第 8 章 8.1.3 节）。

这段为什么重要：它把"记忆"从一句模糊的口号，拆成可落地的分层模型，让你在动手前先想清楚该用哪一类、存在哪一层，而不是把所有东西塞进一个向量库。

> 四类记忆按生命周期与抽象度分派：工作记忆（临时+TTL）/ 情景记忆（事件序列）/ 语义记忆（抽象知识+图谱）/ 感知记忆（多模态）（第 8 章 8.1.3 节，术语见 8.2.5）。

这段为什么重要：分派规则直接决定后续评分公式与存储选型。类型选错，后续的检索与整合都救不回来。

> 记忆形成五阶段：编码 → 存储 → 检索 → 整合 → 遗忘（第 8 章 8.2.1 节，认知启发）。

这段为什么重要：这是记忆系统的生命周期主线，本技能的 I 段骨架就是按这五个阶段展开的。

> RAG 三阶段演进：朴素 RAG（Retrieve-Read + TF-IDF/BM25）→ 高级 RAG（稠密嵌入 + 重写/分块/重排）→ 模块化 RAG（可插拔 / HyDE / 多查询 / 思维链）（第 8 章 8.3.1 节，行业通用）。

这段为什么重要：选型时先定位自己在哪个阶段，避免过早上模块化方案徒增复杂度，也避免停留在朴素 RAG 引入噪声。

> 最小必要原则：四层架构是能力全集，不是每个项目都要全上（第 8 章 8.1.3 节）。

这段为什么重要：它是一把成本尺，直接约束骨架里"该不该上某层"的判断，防止过度设计。

## I — 骨架

下面是可直接照做的结构。所有公式与阈值均来自本书实现，未做任何改写。

### 一、记忆四层架构选型表（F1）

| 层 | 可选组件 | 选型判断 |
|---|---|---|
| 基础设施层 | 计算/存储资源 | 按需 |
| Memory 类型层 | Working / Episodic / Semantic / Perceptual | 按 P4 分派 |
| 存储层 | Qdrant（向量）/ Neo4j（图）/ SQLite（结构化） | 语义+图用 Neo4j，感知/情景向量用 Qdrant，简单结构化用 SQLite |
| 嵌入层 | 嵌入模型 | 注意选错模型会拖垮质量（A1） |

### 二、四类记忆分派清单（P4 / F1）

- [ ] 工作记忆：临时内容 + TTL（默认 TTL 60min，容量默认 50 条）
- [ ] 情景记忆：事件序列（如"用户说过的对话轮次"）
- [ ] 语义记忆：抽象知识 + 图谱（实体/关系）
- [ ] 感知记忆：多模态输入

### 三、记忆形成五阶段流程（F2）

```
编码 → 存储 → 检索 → 整合(consolidate) → 遗忘
```

- 编码：把输入转为可存表示
- 存储：按类型写入对应存储层
- 检索：按下列评分公式取Top-K
- 整合：达到阈值后向上层沉淀（F7）
- 遗忘：触发阈值即清理（P2）

### 四、四类记忆评分公式（F3，本书实现）

```
Working    = (相似度 × 时间衰减) × (0.8 + 重要性 × 0.4)    # 容量默认 50 条 + TTL 60min
Episodic   = (向量 × 0.8 + 近因 × 0.2) × (0.8 + 重要性 × 0.4)
Semantic   = (向量 × 0.7 + 图 × 0.3) × (0.8 + 重要性 × 0.4)
Perceptual = (向量 × 0.8 + 近因 × 0.2) × (0.8 + 重要性 × 0.4)
指数衰减 decay_factor = 0.1
```

### 五、记忆整合与遗忘阈值表（F7 / P2）

| 动作 | 阈值 |
|---|---|
| working → episodic 整合 | 0.7 |
| episodic → semantic 整合 | 0.8 |
| 遗忘：importance_based | 0.2 |
| 遗忘：time_based | 30d |
| 遗忘：capacity_based | 0.3 |

### 六、RAG 处理流程（F5，本书）

```
文档 → MarkItDown → Markdown → 智能分块(标题层次分割 + Token 分块 + 重叠) → 向量化 → 存储
```

智能分块触发条件：原文长度大于 1000 字符时触发（5.4.1）。

### 七、扩展检索"扩展-检索-合并"（F6，本书）

```
1. MQE + HyDE 生成扩展查询
2. 并行检索
3. 去重排序
candidate_pool_multiplier 默认 4
```

### 八、RAG 检索选型规则（P3）

- 一般查询 → 用 MQE
- 专业领域 → MQE + HyDE
- 性能敏感 → 仅基础检索

### 九、记忆隔离与删除清单（P1 / A3）

- [ ] 隔离靠 `user_id` + `rag_namespace`（P1）
- [ ] 删除敏感信息：仅删记录不够，需同时清向量/图库（A3）

### 十、索引增强选项（T 轨）

- [ ] 标题加入索引
- [ ] 自动生成补充索引
- [ ] 图片自动索引

## A1 — 案例

**C1 无状态 Agent 忘记"我叫张三"（8.1.2）**
- 场景：一个不持记忆的 Agent 重启后丢失用户姓名。
- 做法：重启后再次对话，Agent 已不认识用户。
- 可迁移教训：这直接证明了需要记忆系统——凡涉及"跨轮次/跨会话"的个性化信息，必须落记忆层，不能指望上下文窗口。

**C2 智能文档问答助手（8.4，本书）**
- 场景：用户向文档库提问。
- 做法：RAG + Memory 闭环——加载 → 情景记忆 → 高级检索问答 → 报告；承载"检索与记忆协同 / 智能路由"。
- 可迁移教训：检索和记忆不是二选一，闭环里记忆负责跨轮上下文、RAG 负责外部知识，二者协同。

**C3 长程代码库维护助手（9.6，本书）**
- 场景：跨多会话维护大型代码库。
- 做法：TerminalTool 即时探索 + NoteTool 跨会话追踪 + ContextBuilder 筛选，承载"分层上下文 + 断点续传"。
- 可迁移教训：长程任务要把"探索结果"和"进度状态"显式写入记忆，避免每次从零开始（即 A5 上下文腐蚀的对策）。

**C4 健康管理助手设计题（8.5 习题，本书）**
- 场景：设计能记住饮食/运动/睡眠的助手。
- 做法：四类记忆分派饮食 / 运动 / 睡眠。
- 可迁移教训：按"类型分派记忆"是一个可复用套路——先把业务域拆成几类，再逐类映射四类记忆。

## A2 — 触发场景

出现以下任一情况时调用本 skill（判断要具体，不要写"需要记忆时"这种空话）：

- 用户说"我的 Agent 每次重启都忘记之前聊过的内容 / 不记得用户名字"——对应 C1，需要做记忆系统。
- 用户要"给智能体加长期记忆 / 设计四类记忆 / 选工作记忆还是语义记忆 / 设 TTL 和容量"——对应 F1/P4。
- 用户问"记忆怎么整合、什么时候遗忘、consolidate 阈值是多少"——对应 F7/P2。
- 用户要"搭 RAG / 做文档问答 / 文档分块 / 向量化 / 选嵌入模型"——对应 F5。
- 用户问"检索召回低怎么办 / 要不要上 MQE、HyDE、多查询 / 怎么重排"——对应 F6/P3。
- 用户要"多用户隔离的记忆架构 / 删除用户敏感信息要清哪些地方"——对应 P1/A3。
- 用户做"健康管理 / 代码库维护"等需要跨会话记忆的设计题——对应 C3/C4。

## E — 执行步骤

1. **判定是否需要记忆**：问"是否跨轮次/跨会话保留信息？"若否，可能根本不需要（最小必要原则 P5）。产出物：需用/不需用的判断点。
2. **分派四类记忆**：按 P4 把业务域拆类，逐类映射 Working/Episodic/Semantic/Perceptual。产出物：记忆分派表。
3. **选存储层**：语义+图→Neo4j，情景/感知向量→Qdrant，简单结构化→SQLite（F1）。产出物：存储选型。
4. **配评分公式与容量**：套用 F3 公式，工作记忆设容量 50 条、TTL 60min。产出物：评分参数。
5. **设整合/遗忘阈值**：working→episodic 0.7、episodic→semantic 0.8；遗忘 importance 0.2 / time 30d / capacity 0.3（F7/P2）。产出物：阈值表。
6. **做 RAG 链路**：文档→MarkItDown→Markdown→智能分块（>1000 字符触发）→向量化→存储（F5）。产出物：分块+向量化方案。
7. **选检索策略**：一般用 MQE、专业领域 MQE+HyDE、性能敏感仅基础检索（P3）；若扩展检索，设 `candidate_pool_multiplier=4`（F6）。产出物：检索选型。
8. **加隔离与删除机制**：用 `user_id`+`rag_namespace` 隔离（P1）；删除敏感信息须同时清向量/图库（A3）。产出物：隔离+彻底删除清单。

## B — 边界与失效条件

- **不该用/要克制**：不是每个项目都上四层架构，维护成本高，应最小必要（P5/A2）。纯单轮、无个性化需求的任务不必引入记忆。
- **RAG 帮倒忙（A1）**：朴素 RAG 直拼会引入噪声；查询与文档用词差异大时基础检索召回低；嵌入模型选错拖垮质量。→ 此时应升级到高级/模块化 RAG 或换嵌入模型。
- **记忆过度设计（A2）**：四层全上带来高维护成本，按需裁剪。
- **误删敏感信息不彻底（A3）**：仅删记录不够，向量/图库也要清。
- **语义记忆实体抽取可错（A4）**：自动图谱可能抽错实体/关系，关键场景需人工校验。
- **上下文腐蚀 context rot（A5）**：窗口越长回忆越差，长程任务要靠 C3 的显式记忆而非一味拉长上下文。
- **成本代价**：嵌入层与向量存储有算力/存储开销；扩展检索(并行多查询)和高级 RAG 会增加检索与生成延迟与 API 成本。
