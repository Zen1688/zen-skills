# markdown-bulk-edit

**用途**：把「改一份几千行的 Markdown」从**手艺活**变成**可验证的批处理**。
核心不是"怎么改"，而是**"改之前先证明我要改的地方确实存在、且只存在一处"**。

## 何时该用

满足任一条即用本工作流，**不要**手工逐条 Edit：

- 需要在同一文档上做 **3 处以上**替换
- 文档 **> 500 行**，或单行 **> 300 字符**
- 改动涉及**编号体系**（`N1~N31` / `D28~D40` / `I1~I30`）或**版本号**
- 改完后需要**向人证明**"没有遗漏、没有残留"
- 改动需要**可回滚**（出问题能重来）

不适用：单处小改、纯新增一节（用 Write/Edit 直接写）。

## 一、铁律：写盘前校验，不通过就不写

```python
def rep(s, old, new, tag, checks):
    n = s.count(old)
    checks.append((tag, n))
    if n != 1:
        print("MISS[%s] count=%d" % (tag, n)); return None   # 只报告，不动作
    return s.replace(old, new, 1)

# ...
bad = [c for c in checks if c[1] != 1]
for tag, n in checks:                       # 逐项打印，肉眼可核
    print("  %-24s %s%s" % (tag, n, "" if n == 1 else "   <<<< CHECK"))
if bad:
    print("!! 有 %d 项未唯一命中，未写盘" % len(bad))
    sys.exit(1)                             # ← 关键：校验失败绝不落盘
open(P, "w", encoding="utf-8", newline="").write(s)
```

**为什么必须这样**：整批替换是"全成或全败"的操作。
一项没命中而其余写盘 ⇒ 文档**半新半旧**，比不改更糟（顶部摘要与正文矛盾，最难查）。
把 `sys.exit(1)` 放在写盘之前，整个文档天然具备**原子性**。

**实战战绩**：某次 25 项替换的校验当场抓出 1 处「页脚行尾少一个 `*`」，
若手工改会**静默漏改**且事后无任何报错。

## 二、四级匹配策略（从强到弱，择强而用）

| 级 | 手法 | 适用 | 风险 |
|---|---|---|---|
| ① | **整行精确匹配**（含首尾字符） | 唯一行、结构行 | 最安全，但对不可见字符零容忍 |
| ② | **按行首前缀定位 ＋ 整行替换** | 表格行、`- ` 列表行（`startswith`） | **推荐默认**，抗尾部差异 |
| ③ | **`str.index()` 切片替换** | 引号/符号已被规范化、难抄 | 需自己校验唯一性 |
| ④ | **正则 `re.sub`** | 模式化批量（如所有 `v1.9` → `v2.0`） | 用 `count=` 限次并回读校验 |

② 是主力手法。表格行、条目行只要**行首前缀唯一**就够：

```python
def repline(s, prefix, new_line, tag, checks):
    lines = s.split("\n")
    idx = [i for i, l in enumerate(lines) if l.startswith(prefix)]
    checks.append((tag, len(idx)))
    if len(idx) != 1:
        print("MISS[%s] lines=%d" % (tag, len(idx)))
        for i in idx: print("   ", lines[i][:110])   # 命中多处时打印候选，便于收窄前缀
        return None
    lines[idx[0]] = new_line
    return "\n".join(lines)
```

命中多处时**打印候选**很重要 —— 你可以立刻看出该把前缀加长到什么程度。

## 三、不可见字符陷阱（实测踩过的，全部要防）

| 陷阱 | 症状 | 对策 |
|---|---|---|
| **弯引号 vs 直引号** | 你写 `"x"`，文档里是 `“x”`（U+201C/U+201D） | 从 `Read` 输出里**整段复制**，别手打 |
| **emoji 变体选择符** | `✅` 匹配不到 `✅️`（后者带 U+FE0F） | 避开 emoji，改用相邻的稳定文字做锚点 |
| **行尾 `*` / 空格** | 你以为行尾有 `*`，其实没有 | 用 ② 行首前缀法，绕开尾部 |
| **全角/半角括号** | `（` vs `(`、`「」` vs `"` | 同上：复制而非手打 |
| **`wc -m` vs `wc -c`** | 字符数对不上（中文 1 字符 = 3 字节） | 判断"超限"用 `wc -m`（字符），排查编码用 `-c`（字节） |
| **CRLF** | 写盘后全篇 diff | 写盘统一 `newline=""` ＋ `encoding="utf-8"` |

**通用心法**：拿不准时先 `print(repr(line))` 把目标行打出来看转义 —— 一次就定位。

## 四、改完必做的反查（缺一不可）

用**独立脚本**（不是改稿脚本）跑，逐项打印数字：

```python
import re
s = open(P, encoding="utf-8").read(); t = s.split("\n")

# 1) 编号连续性（最容易错、也最容易自动查）
ns = sorted({int(m) for m in re.findall(r"\*\*N(\d+)\*\*", s)})
print("N:", ns[0], "~", ns[-1], "连续=", ns == list(range(1, len(ns) + 1)))

# 2) 版本号一致（顶部声明 vs 页脚记录）
print("v2.0 =", s.count("v2.0"), " v1.9 =", s.count("v1.9"))

# 3) 表格完整性：空行夹在两条 | 行之间 = 表格被截断
bad = [i+1 for i in range(1, len(t)-1)
       if t[i].strip() == "" and t[i-1].startswith("|") and t[i+1].startswith("|")]
print("表格断裂:", bad)          # ⚠️ 相邻两表间的正常空行会假阳性，须人工确认

# 4) 旧表述残留（关键！否则顶部与正文自相矛盾）
for kw in ["阻塞 4.5", "须在开工前拍板", "待定", "TBD"]:
    hits = [i for i, l in enumerate(t, 1) if kw in l]
    print("  %-16s %d  %s" % (kw, len(hits), hits))   # 逐处打开确认是历史段还是真残留

# 5) 临时文件清理
import os
print("临时残留:", [f for f in os.listdir(D) if f.startswith("_tmp")])
```

**反查的两个要点**：

1. **旧表述残留要逐处打开看**，不能只看计数。历史段落里的旧表述是**合法的**（记录当时状态），
   但必须**加时效注记**（`（✅ 已于 YYYY-MM-DD 拍板：…）`），否则读者无法区分"历史"与"现状"。
2. **顶部版本行 / 摘要段必须同步**。正文改了、顶部没改 ⇒ 全文最强误导源。

## 五、改「编号体系」文档的额外规程

编号系列（`N` / `D` / `I` / `B` / `NC`…）是文档的骨架，改动前：

- **先反查该字母是否已被别的系列占用** —— 撞号后只能让位，代价高
- **新增条目后跑连续性检查**（上面第 1 项）
- **改了某编号的定性，必须回查正文里所有引用它的地方**：用 `grep -rn "<编号>"` 覆盖全部相关文档
- **手法**：拿**新能力**去反查**所有旧的"全称否定句"**（如"三处全部可注入" ⇒ 实测 5 处后必须回头改这句）

```bash
grep -rn "N24" doc-a.md doc-b.md docs/     # 引用它的每一处都要核对
```

## 六、留痕与回滚

- 脚本走 `Write` 落成 `.workbuddy/_tmp_<用途>.py`，**用完全部清掉**（别留在仓库里）。
  ⚠️ **清理别用 `rm`** —— 某些环境（实测 WorkBuddy 的 Git Bash 沙箱）里 `rm` 被 shim 包装，
  会报 `dirname: command not found`、**exit 127，但文件仍在**（**已 `export PATH` 也照样失败**，
  因为 shim 自己覆盖了 PATH）⇒ 用 **Python `pathlib.Path(f).unlink()`**，跑完 `ls`/`git status` 复核。
  🔑 **教训同 §8.3**：「退出码 127」是**失败信号**，但**别把它当成功**；凡"清理"动作，必须**回读目录确认**。
- 脚本头部写清用途与目标文件路径 —— 它本身就是**操作日志**
- 大改前 `git status` 记录 HEAD，改完再对一次：**能一眼看出"只动了预期的那一个文件"**
- 若宿主有版本控制，**改稿与 commit 分开**：改完先给人看，得到确认再提交

## 七、反面教材

| 做法 | 后果 |
|---|---|
| 用 Edit 工具连续替换十几处 | 一处不匹配就中断，前功尽弃；且**跨文件多条编辑会被静默丢弃** |
| 边改边写盘（不预校验） | 半新半旧文档，查错成本远超重做 |
| 手打中文引号/括号 | 匹配失败，且失败原因**肉眼看不出来** |
| 只改"被点名的那一行" | 旧表述残留在别处，全文自相矛盾 |
| 改完不做反查 | 编号断号、表格截断、版本号不一致，全部事后才暴露 |
| 临时脚本留在仓库 | 污染工作区，`git status` 变脏 |

## 八、09-19 ~ 09-20 追加：五条实测教训（都踩过、都留了痕）

### 8.1 整行替换的「命中 1/1」只证明定位对，**不证明内容无损**

按行首前缀替换**整行**时，**该行独有的符号会被一并抹掉**。
实测：替换「下一步 ＝ 4.5」这一行，把**全文件唯一**的 `N25 ⓑ1 ＋ N29` 一起删了
（该圈号码点计数 **1 → 0**），而命中数显示 **1/1 完全正常**。

✅ **规程**：整行替换后，额外做一次**符号级对账** —— 对「被替换行里原有的关键符号
（编号、方法名、圈号）」逐个计数，确认**不是 0**。命中数是**定位判据**，不是**内容判据**。

### 8.2 罕见圈号：形近字陷阱，且**回显也不可信**

| 形近对 | 说明 |
|---|---|
| `ⓑ` **U+24D1** vs `⑑` **U+2451** | CIRCLED LATIN SMALL LETTER B vs CIRCLED DIGIT … 极像 |
| `①` U+2460 vs `⑴` U+2474 vs `⒈` U+2488 | 圈号 / 括号号 / 数字点号 |

实测：锚点里手打 `ⓑ`，落进工具后变成 `⑑` ⇒ 命中 **0/1**；
**Edit 工具报错时的回显也把 `ⓑ` 显示成 `⑑`** ⇒ **回显不能用来判断原文**。

✅ **手法**：脚本里用 **`"\u24d1"` 转义构造**（源码全 ASCII，绕开形近混淆），
并在脚本末尾加 **「该码点计数」自检**（期望值写死）。⚠️ 对**新增文本**同样适用 —— 不只是锚点。

### 8.3 反查脚本自己的判据也会「太宽」

判「粗体是否闭合」时若直接 `s.count('**')`：
**行内代码里的两个星号**（文档在讲 `**` 本身时必然出现）会被**误计成粗体标记**
⇒ 报出「**奇数 ⇒ 粗体不闭合**」的**假红**，而真文本其实是闭合的。

✅ 判据改为：**先正则剥掉「反引号包裹的行内代码段」，再数标记判奇偶**。

⚠️ **并且绝对值不可用**：`count('**')` 的绝对值会被行内代码抬高、**天然可能是奇数**
（实测某 500 行工作日志 ＝ **1033**）⇒ **只判剥离后的奇偶，⛔ 不判绝对值**；
文件级对账一律用 **Δ（改前 → 改后）**，不用绝对量。

> 这条与本技能 §一 的「铁律」是**同一个病**的两端：
> **判据太宽**（覆盖了不该覆盖的对象）与**判据不存在**一样会造成静默失效 ——
> 只不过前者表现为**假红**，后者表现为**假绿**。写反查脚本时，
> **先问一句「这个判据会不会把不该算的东西也算进来」。**

### 8.4 污染字符检测：一律做**增量比较**，⛔ 不做「存在性」判断

8.3 的 Δ 原则不止用于格式标记 —— **「文件里有没有可疑字符」这个判据天然会误报**，
因为文档里可能**正在讨论这个字符本身**。

实测（09-20）：脚本里写 `if 文件含 U+2451: 报警`，结果被**同一份文档里那句正当正文**
「`U+24D1 ⓑ` vs `U+2451 ⑑` 形近但码点不同」（教训记录，必须保留）**假红拦下** ——
**同族病第二次复发**（第一次是 `**` 奇偶，见 8.3）。

✅ **判据模板 —— 只查「单向不利」的增量**：

| 检查项 | 报警条件 | 理由 |
|---|---|---|
| 信息符号（编号 / 方法名 / 圈号） | **新值 < 旧值** | 少了才是丢失 |
| 污染符号（形近字 / BOM / 全角空格） | **新值 > 旧值** | 多了才是污染 |
| 成对标记（`**` / 反引号 / 括号） | 仅判**剥离行内代码后的奇偶** | 绝对值不可用 |

> 统一形式：**比较 `s_new` 与 `s_old` 的 Δ，落在不利方向才报警。**
> 把「**有没有**」换成「**变多了还是变少了**」，假红立即消失，且不牺牲灵敏度
> （真污染必然表现为「多了」，真丢失必然表现为「少了」）。

### 8.5 反引号奇偶：还须**先剔除代码围栏行**

09-20 实测（404 行文件）：反引号 **533 ＝ 奇数** ⇒ 初判「有未闭合标记」。
逐行查后真相：**奇数行全部是代码围栏**（`` ``` `` ／ `` ```bash `` ／ `` ```powershell ``，每行恰 **3** 个）
＋ 一处**跨 2 行的行内代码**。而**新增的 21 行合计 46 ＝ 偶、段内零奇数行** ⇒ 与改动**无关**。

⇒ **围栏行天然含奇数个反引号**（` ``` `＝3），把它算进奇偶 ＝ **判据选错对象**（8.3 家族**第三次**）。
✅ 可直接用的判据：

```python
def paired_ok(text: str) -> bool:
    """成对标记是否闭合 —— 先剔两类「合法的奇数」来源（围栏行、行内代码），再判。"""
    lines = [l for l in text.splitlines() if not l.lstrip().startswith("```")]
    s = re.sub(r"`[^`]*`", "", "\n".join(lines))
    return s.count("**") % 2 == 0
```

> **判据三连**（§8.3 → §8.4 → §8.5）其实是**同一条**：
> 先问「**我把什么算进来了**」（对象是否选错），再问「**该看绝对值还是增量**」（口径是否选错）。
> 两次实测都证明：**误报几乎全部来自这两问没问**，而不是来自判据本身写错。

### 8.6 反查脚本自己算错 ⇒ **假绿**（比假红危险得多）

10-05 实测：写一组「新值是否落地」的批量扫描，形如

```python
for k, v, src in [("03|48 层", t3, "48 层"), ...]:
    print(src, {"03": t3, "01": t1}[k.split("|")[0]].count(v))
```

变量三件套（`k` 标签 / `v` 待查值 / `src` 显示名）**串了位** —— `v` 被传成了**文件全文**，
于是 `.count(v)` 退化成 `t3.count(t3) == 1`。结果 **14 项检查全部输出「1」，看上去项项通过**，
而真正要查的关键词**一次都没查过**。是靠另一条 grep 交叉核对才发现的。

⇒ 三条硬规矩：

1. **被测对象不得同时充当比较基准。** 断言必须写成「期望值 vs 实际值」两个独立量：
   `print(kw, "expect>0, got", text.count(kw))`；**永不**写 `A.count(A)` 型表达式。
2. **假绿比假红危险。** 假红会被人工复核掉，假绿会直接写进结论。
   凡批量自检出现「**全部通过**」，必须**抽 1~2 项用独立工具（grep）交叉复核**。
3. **输出要能看出"查了什么"。** 打印「关键词 + 期望 + 实际」三列。
   只打印 `OK` / `1` 的输出，串位了你也看不出来。

> 与前面的关系：§8.3~8.5 治的是**假红**（判据太宽 / 对象选错），§8.6 治的是**假绿**（读数本身错）。
> 一套自检里 **两类都要防**——先保证「查的是对的东西」（8.6），再保证「判据不乱覆盖」（8.3~8.5）。

## 九、10-05 追加：插入语义（insert）与可回滚 diff

前面所有规程默认是**替换**（整段改写）。**插入**（在锚点前/后新增区块）多出三类专属风险，实测都踩到：

### 9.1 空行纪律：插入块的块首自带空行

Markdown 里「块与块之间必须有空行」。`ins_after(lines, prefix, block)` 若把 block 直接贴在锚点行后面、
而 block **首行是标题**，就会得到：

```
> **正文引用块**……
### 7.6 新章节标题        ← 标题被吞进引用块，渲染错乱
```

✅ **规程**：把空行写进 block 本身（首部补一个空元素，或在 block 末尾补 `\n` 让 `split("\n")` 产出空尾元素）。
**别指望锚点周围本来就有空行**——锚点常常正好是「块的最后一行」（如引用块末行），其后紧跟的是分隔符 `---`。

### 9.2 锚点选字：避开圈号 / 弯引号 / emoji

§8.2 的形近字陷阱在**选锚点**时同样成立。实测有效做法：锚点只用 **ASCII + 常规 CJK 汉字**，
不碰 `①④`、`「」`、`“”`、emoji。例：锚点取 `"查询改写的价值。"`（纯汉字）而非含 `④` 的原句 —— 手打圈号一旦落成形近码点，
命中数就是 0，且**回显也不可信**（§8.2）。

### 9.3 插入场景要补三项结构反查

替换时 §8.1 要求补「符号级对账」；插入时要补**结构反查**，至少三项：

| 判据 | 检查什么 |
|---|---|
| **标题隔离** | 每个 `^#` 行的上一行与下一行都必须是空行（首行除外） |
| **行尾空白** | 非围栏行不得有行尾空格（block 里手写的 `"> "` 最容易留） |
| **编号连续性** | 新增小节后重跑 `^### N\.(\d+)` / `^\| (\d+) \|` 的连续性检查 |

### 9.4 可回滚 diff：先重建 pristine，**字节级对账后**才信 diff

改稿前若**没有备份**，又需要行级 diff 与回滚路径 —— 只要「原始内容有确定性的生成源」
（如云端导出的组件原文 + 转换器），就能重建 pristine：

```python
# 1) 用同一转换器把 pristine 重建到临时目录
# 2) ⚠️ 关键：先证明重建版与"改前状态"逐字节一致（行数 / 字节数逐文件对账）
#    对不上 ⇒ diff 全是噪声，先查清差异来源，别急着下结论
# 3) 再 diff -u pristine current，变更块行号才可作为证据
```

实测记录：5 个文件重建后 `61894 B/1230 行`、`32990 B/585 行`、`28574 B/341 行` 全部与改前基线吻合，
`diff -u` 报 README/01 **hunks=0**、其余 **3 / 3 / 1** 块 —— 与预期改动完全对应，
这才有资格对用户说「只动了预期的地方」。把 diff 落到 `<repo>/.workbuddy/<用途>.diff` 留痕，临时脚本随之清理。

### 9.5 插入辅助函数的「锚点重复」陷阱（实测）

写 `ins_after(lines, prefix, block)` 时，一个极易犯的错：**在调用处又把锚点行本身塞进 block**。

```python
# ✗ 错：pos="after" 已保留锚点，block 里再带一次 ⇒ 锚点行出现两遍
lines = lines[:i+1] + [anchor_line, new_line] + lines[i+1:]
```

症状：脚本报「改动成功」，锚点行却在文中出现两次 —— 肉眼在一屏内**不一定看得出**，尤其在**完全对称的 ASCII 框线图**里。
本次实测就在 README 的学习路线图框里复制出了一行 `│ → Agent 架构 → …… │`。

✅ **规程**：
1. 语义定清 —— `before` 只在锚点前插、`after` 只在锚点后插，**block 永远不含锚点行**；
2. 插入后补一条**去重反查**：`[l for l in lines if l == anchor]` 的长度必须仍为 1（不是 2）；
3. 对称结构（ASCII 框线 / 易重复的表行）额外做**显示宽度逐行比对** —— 重复行宽度也一致，靠宽度能一次定位。

### 9.6 围栏奇偶：先分清「全文计数」与「行首计数」

反引号奇偶有两个口径，**混用会自造假警报**（实测各踩一次）：

| 口径 | 写法 | 适用 / 风险 |
|---|---|---|
| 全文计数 | `text.count("```")` | 判成对闭合；**会被正文里的内联三反引号污染** |
| 行首计数 | `len(re.findall(r"^```", text, re.M))` | 判围栏块数，抗内联污染 |

两个坑：

1. **内联三反引号破坏全文计数**：正文若写「以 ```` ```mermaid ```` 代码块内嵌」，该行即含 3 个成组反引号 ⇒ 奇偶瞬间翻车。
   ✅ 正文描述改用**单反引号**（`` `mermaid` ``），把三反引号留给真正的围栏。
2. **错把「行列表」当「全文」**：`lines.count("```")`（lines 为 `split("\n")` 的结果）数的是**恰好等于 ``` 的行数**，
   与奇偶毫无关系，却会打印出一个看似有意义的数字。⇒ **计数前先确认对象是 list 还是 str**，输出里带上单位（"全文计数 / 行首计数"）。

## 十、10-05 追加（第二批）：跨文档对比与 diff 留痕的四个坑

### 10.1 跨文档对比：基线必须**同期重算**，⛔ 不能沿用旧值

**场景**：拿 A 文档的「行/章」去比 B 文档，判断"谁更厚"。若 A 的基线取自**上一批次**，
而**本批次又改了 B**，比较立刻失效 —— 实测就是这样：

| 环节 | 数值 | 问题 |
|---|---|---|
| 设定目标时 | 目标册 `124.5` vs 参照册 `122.9` | 参照册 122.9 = **批 3 后**旧值 |
| 本批次结束时 | 目标册 `124.5` vs 参照册 **`126.7`** | 本批次同时给参照册加了 43 行 ⇒ **结论反转** |

原本「已超过」的结论变成了「仍未超过」，**而所有数字单独看都"没错"**。

✅ **规程**：
1. 定目标时记下**参照基准值 + 取值来源（哪个检查点）**；
2. 收口时**重算参照值**，两个数都取自**同一时点**；
3. 比较结论写进产出物时，**同时写出参照值**（`127.7 > 126.7`），别只写"已超过"。

> 这与 §8.4 的 Δ 原则同源：**绝对值没有意义，同一个时间切片上的两个值才有意义。**

### 10.2 指标口径要一次性钉死，并写进产出物

同一份文档里出现「55 行/章」「124.5 行/章」「34+16+2=52 处」却标注为「42 处」——
根因是**口径混用**，实测三种：

| 混用点 | 常见写法 A | 常见写法 B |
|---|---|---|
| 行数分母 | **全文行数**（含 `## 结语`） | **正文行数**（不含结语） |
| 章数分母 | 含 `## 结语` 记作一章 | 不含结语 |
| 分类计数范围 | **本批次新增**（42 处） | **全册累计**（52 处） |

✅ **规程**：产出物**开头一句写死口径**，例：
`（口径统一为「全文行数 ÷ 章数」，章数不含 ## 结语）`；
分类计数一律写成「**本批次新增 X / 累计 Y**」两段式。
⚠️ 更隐蔽的一种：**同一张表里混用两个口径**（`42 处` 用增量口径、`34+16+2` 用累计口径），
两个数各自都对、合起来矛盾 —— 收口时对每一行做一次「**这一行的口径和上一行一致吗**」的自问。

### 10.3 生成 unified diff：注释头行必须**带换行**；解析端改用 `+++ tofile/` 切分

自己拼 diff 文件时最容易犯的错：**头部注释行没写 `\n`**，于是下一行 `--- fromfile/x.md` 被**拼进注释行**：

```
# 变更记录（unified diff）# 左 = 备份   右 = 现行--- pre-batch3/README.md   ← 这一行的 --- 头被吞了
+++ current/README.md
@@ ...
```

后果：`---` 头少了 2 个（该文件在按 `--- ` + `+++ ` 配对切分的解析器里**整块丢失**），
重建出的文件「**一个字节都没变**」，而你只会看到「重建失败」，很难联想到是**自己写的 diff 头缺换行**。

✅ **两条规程**：
```python
# 生成端：逐行归一化，缺换行的补上
norm = ''.join(x if x.endswith('\n') else x + '\n' for x in out)
io.open(p, 'w', encoding='utf-8', newline='').write(norm)

# 解析端：用 +++ tofile/ 切分（+++ 永远在行首，不会被子行吞掉）
for l in dl:
    if l.startswith('+++ current/'):
        cur = l[len('+++ current/'):].strip(); per[cur] = []
    elif cur is not None:
        per[cur].append(l)
```
⚠️ 解析端还要**过滤掉 `--- ` / `+++ ` 残留行**（它们会落在上一文件的桶里），
并**逐个文件对账重建结果的字节数**（§9.4），对不上就先查 diff 源本身，别去改 `apply` 函数。

### 10.4 `grep -c` 配 `&&`：**0 匹配会静默跳过后续命令**

```bash
grep -c '^```mermaid' f.md && echo "===== next ====="   # f.md 里 0 处
```
`grep -c` 计数为 **0 时退出码 = 1** ⇒ `&&` 右侧整段**不执行**，但**屏幕上没有任何报错**
（只有那个孤零零的 `0`）。实测就是靠这行「少打印了一段分隔符」才发现的 ——
如果被跳过的是**校验命令**，就等于**静默少跑了校验**（§8.6 的假绿家族）。

✅ **规程**：计数类命令**一律不用 `&&` 串联**，改用 `;` 或直接写进 Python；
需要"0 也要算成功"时写 `grep -c ... || true`。凡脚本输出里出现**段落级缺失**，先怀疑是这一条。
