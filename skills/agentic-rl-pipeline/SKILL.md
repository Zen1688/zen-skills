# Agentic-RL 训练流水线（agentic-rl-pipeline）

## R — 原理锚点

> "Agentic RL：将 LLM 作为可学习策略，嵌入感知—决策—执行循环，通过强化学习优化多步任务表现。"（第11章 11.1.1 节）

这段为什么重要：点明 Agentic RL 与传统单轮后训练的本质区别——优化对象是"多步决策循环"而非单条回答质量。

> "Agentic RL 把状态定义为 sₜ=(prompt,o₁…oₜ)，行动含 {a_text, a_tool}，奖励为 Σγᵗr(sₜ,aₜ)。"（第11章 11.1.3 节，表 11.1）

这段为什么重要：状态随观测扩展、行动可含环境操作、奖励可中间给分，这三点是它能学"会调工具"的前提。

> "Agentic RL 六大核心能力：推理、工具使用、记忆、规划、自我改进、感知。"（第11章 11.1.3 节，图 11.2）

这段为什么重要：每项都指明 RL 相对 CoT/SFT 的增量（如记忆：学会何时记/更新/删除，而非静态 RAG），是设计训练目标的坐标。

> "必须先 SFT 再 RL：预训练模型输出无结构，无法提取答案、无法评估、无法给奖励信号。"（第11章 11.3 节）

这段为什么重要：这是整条流水线的顺序约束，跳过 SFT 直接 RL 往往失败，决定了训练阶段的先后。

> "GRPO 用组内相对奖励 r−r̄_group 代替需 Value Model 的优势函数，只需 Policy+Reference 两模型。"（第11章 11.4.1 节）

这段为什么重要：相比 PPO 省掉 Value/Reward 两模型，显存与实现成本大幅下降，是本书主推的 RL 算法。

## I — 骨架

### 骨架一：PBRFT vs Agentic RL 的 MDP 五元组对照（第11章 11.1.3 节，表 11.1）

| 维度 | PBRFT | Agentic RL |
|---|---|---|
| 状态 | s₀=prompt，T=1 | sₜ=(prompt,o₁…oₜ)，T≫1 |
| 行动 | 仅文本生成 | {a_text, a_tool}（含环境操作）|
| 转移 | 无转移 | sₜ₊₁~P(·\|sₜ,aₜ) |
| 奖励 | 仅终局单步 | Σγᵗr(sₜ,aₜ)，可中间给分 |

### 骨架二：端到端训练流水线六阶段（第11章 11.6.1 节，AgenticRLPipeline）

```
数据准备 → SFT 训练 → SFT 评估 → GRPO 训练 → GRPO 评估 → 保存/部署
```
配置内置 `sft_accuracy_threshold: 0.40` 作为从 SFT 放行进入 RL 的门槛。

### 骨架三：GRPO 训练循环五步（第11章 11.4.3 节）

```
1. 采样 num_generations 个答案成"组"
2. 逐个算奖励
3. 减组内均值：相对奖励 r̂ᵢ = rᵢ − r̄
4. 带 KL 惩罚更新策略
5. 循环
```

### 骨架四：三类评估指标体系（第11章 11.5.1 节）

| 类别 | 指标 |
|---|---|
| 准确性 | Accuracy / Accuracy@K / 数值误差 |
| 效率 | 平均长度 / 推理步数 / 推理时间 |
| 质量 | 格式正确率 / 推理连贯性 / 可解释性 |

### 骨架五：四类错误归因框架（第11章 11.5.3 节）

| 错误类 | 含义 | 指向能力短板 |
|---|---|---|
| 计算错误 | 步骤对、算错 | 数值能力 |
| 推理错误 | 思路错 | 推理能力 |
| 理解错误 | 没读懂题 | 理解能力 |
| 格式错误 | 缺 `Final Answer:` | 输出格式 |

### 骨架六：分布式方案选型（第11章 11.6.3 节）

| 规模 | 方案 |
|---|---|
| 2–8 卡 | DDP |
| >7B 模型 | DeepSpeed ZeRO-2 / ZeRO-3 |
| 多节点集群 | ZeRO-3 + CPU Offload |

### 骨架七：带理由的参数阈值集合（第11章 11.3.3 / 11.4.2 节）

| 参数 | 推荐值 | 理由 |
|---|---|---|
| num_epochs | 从 3 起 | <2 欠拟合，>10 过拟合 |
| batch_size | 4GB→1-2 / 8GB→4-8 / 16GB→8-16 | 按显存 |
| warmup_ratio | 0.1 | — |
| weight_decay | 0.01 | — |
| lora_rank | 4-8 小任务 / 16-32 复杂 / 64 大规模 | 按任务 |
| num_generations | 4-8 | GRPO 组大小 |
| max_new_tokens | 256-512 | — |
| temperature | 0.7-1.0 | 保留探索性 |
| kl_coef | 0.05-0.1 | 0.01 偏离过远，0.5 学不动 |
| clip_range | 0.2 | — |
| SFT 学习率 | 5e-5（LoRA 可 1e-4） | — |
| GRPO 学习率 | 1e-5~5e-5 | 须小于 SFT，不希望偏离 SFT 太远 |

> 梯度范数应落在 0.1–10（11.3.3(3)）：>100 梯度爆炸需降 lr，<0.01 梯度消失需查模型配置。
> KL 散度应维持 0.01–0.1（11.4.3(3)）：>0.5 策略跑偏（增 kl_coef 或降 lr），<0.001 几乎没更新（反向调）。
> `batch_size` 必须能被 `num_generations` 整除（11.1.5）。

### 骨架八：其它原则（P 轨）

- 长度惩罚 / 步骤奖励只在答案正确时才施加（11.2.2）：否则模型会为减惩罚而生成错误短答案。
- 从小规模开始迭代（11.6.1）：先 100–1000 样本验证流程与参数再放大。
- 训练前做数据质量三查：必需字段、空值、重复样本（11.6.1）。
- 分布式必须保持总 batch 一致并按平方根缩放 lr（11.6.3）：总 batch = per_device × num_gpus × grad_accum；lr_new = lr_base × √(new/base)。
- LoRA 建议默认开启，除非显存充足（11.3.3(1)）。

## A1 — 案例

**预训练 vs SFT 输出对照实验（第11章 11.3.1 节）**
- 场景：同一 GSM8K 题，验证模型是否具备进入 RL 的结构。
- 做法：预训练模型输出"…我不确定怎么算 48 的一半，也许该用计算器？"——冗长、无结构、无答案；SFT 后输出 Step 1 / Step 2 / `Final Answer: 72`。
- 可迁移教训：这是判断"能不能进入 RL 阶段"的实操验收标准——SFT 输出须有结构与最终答案。

**GRPO 相对奖励手算示例（第11章 11.4.3(1) 节）**
- 场景：理解 GRPO 为何能降方差。
- 做法：4 个答案奖励 [1.0, 1.0, 0.0, 0.8] → 均值 0.7 → 相对奖励 [+0.3, +0.3, −0.7, +0.1]。
- 可迁移教训：GRPO 鼓励"比组内平均更好"而非绝对高分，这是它降方差的机制所在。

**难度分层准确率剖面（第11章 11.5.3 节）**
- 场景：定位下一轮改进方向。
- 做法：简单（1-2 步）78.5% / 中等（3-4 步）58.3% / 困难（5+ 步）31.6%；错误分布计算 42.1%、理解 28.9%、推理 23.7%、格式 5.3%。
- 可迁移教训：格式错误低说明 SFT 到位，计算错误高指向数值能力；用"分层准确率 + 错误归因"两张表定位，而非只看总准确率。

## A2 — 触发场景

在以下具体情况下应调用本 skill：
1. 需要训练一个能多步决策、调工具、带记忆的 Agent（定义 11.1.1）。
2. 要判断"当前模型能不能进入 RL 阶段"——看 SFT 输出是否有结构（预训练 vs SFT 对照）。
3. 要做 SFT 或 GRPO 训练，需要参数阈值与故障归因。
4. GRPO 训练时奖励不涨 / KL 爆炸 / 准确率升但质量降。
5. 需要设计奖励函数（稀疏 / 密集 / 混合）并避免奖励欺骗。
6. 需要评估 Agent 训练效果（准确性 / 效率 / 质量 + 错误归因）。
7. 资源受限（如 0.6B / 7B 模型、消费级 GPU）想做 SFT 或 RL。

## E — 执行步骤

1. **数据准备**：SFT 格式 `{prompt, completion}`（含完整推理过程）；RL 格式 `{prompt, ground_truth}`（仅最终答案，迫使模型自主生成推理）。做数据质量三查（必需字段 / 空值 / 重复样本）。产出：训练数据集。
2. **SFT 训练**：默认开 LoRA；lr 5e-5（LoRA 1e-4），num_epochs 3 起，batch_size 按显存，warmup_ratio 0.1，weight_decay 0.01。产出：SFT 模型。
3. **SFT 评估**：用 GSM8K 等验收——输出须含 Step 与 `Final Answer:`（参考预训练 vs SFT 对照），准确率需达 `sft_accuracy_threshold: 0.40` 才放行。产出：SFT 评估报告。
4. **奖励设计**：选稀疏 / 密集 / 混合；长度惩罚与步骤奖励只在答案正确时施加；避免奖励欺骗与多目标矛盾。产出：奖励函数。
5. **GRPO 训练**：lr 1e-5~5e-5（< SFT），num_generations 4-8，batch_size 能被 num_generations 整除，kl_coef 0.05-0.1，clip_range 0.2，temperature 0.7-1.0。产出：RL 模型。
6. **监控指标**：梯度范数 0.1–10，KL 散度 0.01–0.1；异常按故障归因处理。产出：训练曲线。
7. **GRPO 评估**：三类指标（准确性 / 效率 / 质量）+ 四类错误归因（计算 / 推理 / 理解 / 格式）+ 难度分层准确率。产出：评估与改进方向。
8. **部署**：达放行门槛后保存；分布式按 DDP / ZeRO 选型，保持总 batch 一致并按 √ 缩放 lr。产出：部署模型。

## B — 边界与失效条件

- **不该用**：纯单轮对话质量优化属 PBRFT 范畴（11.1.3 对立），非 Agentic RL，应走传统后训练。
- **风险（跳过 SFT 直接 RL）**：模型连基本输出格式都不会，无法提取答案 / 计算奖励，往往失败（11.3 开篇）。
- **风险（奖励函数四病征）**：仅终局给奖励 / 存在奖励欺骗 / 多目标互相矛盾 / 方差过大不收敛（11.2.2）。
- **风险（准确率奖励稀疏）**：无法区分"接近正确"与"完全错误"（11.2.2(1)）。
- **风险（长度/步骤奖励）**：长度惩罚抑制详细推理；步骤奖励诱导冗余步骤且检测可能不准（11.2.2(2)(3)）→ 组合须仔细调 α、β。
- **风险（LoRA 效果）**：通常比全量微调更差，勿把"参数高效"当"效果无损"（11.3.2）。
- **风险（GRPO 显存 OOM）**：因需同时生成多个答案并存参考模型输出（11.4.3 末）；缓解：num_generations 8→4、batch_size 4→2、max_new_tokens 512→256、梯度检查点、混合精度。
- **GRPO 三故障**：① 奖励不涨 = lr 太小 / KL 太大 / 奖励不合理 / SFT 太差；② KL 爆炸（>0.5~1.0）致格式混乱 = lr 太大 / KL 太小 / 奖励过激进；③ 准确率升质量降 = 奖励只看准确率 / KL 太小 / 过拟合（11.4.3(3)）。
- **SFT 故障**：损失不降 = lr 太小或数据格式问题；先降后升 = lr 太大或过拟合；显存不足 = 减 batch / max_length、梯度累积（11.3.3(3)）。
- **资源门槛**：0.6B 全量微调约 12GB(FP16) / 24GB(FP32)；7B / 13B "几乎不可能在消费级 GPU 上"（11.3.2、11.6.3）。完整 SFT（7473 样本、3 epoch、8GB 显存）预计 30–60 分钟。
- **小样本试跑陷阱**：只见过 0.7% 训练样本且只跑一轮，准确率极低属正常（11.1.5）→ 勿以快速测试判方法有效性。
- **能力天花板**：Qwen3-0.6B 在 GSM8K 上 SFT 后 40–50% 正常，RL 后可到 60–70%（11.3.4）。
- **调参搜索**：网格搜索参数多时不可行；随机搜索可能错过最优；贝叶斯优化实现复杂需额外库（11.6.2）。
- **已知自相矛盾**：`lora_alpha` 一处说"等于 rank"、一处说"2 倍"（11.3.2 vs 11.3.3(1)）；示例代码全用 2 倍（rank=8→alpha=16，rank=16→alpha=32）→ 以示例 2 倍为准，但非唯一定论。

## 配套技能

本技能是 **AI Agent 全生命周期套件**（`zen-agent-suite`）的第 10/10 环。
