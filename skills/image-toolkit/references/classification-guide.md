# 分类判据原理与自定义规则调优指南

## 一、分类是怎么算出来的

分类结果 = **OCR 文本关键字命中** + **图像客观特征补正**，两者加权后给出置信度。

```
置信度 = min(强关键字数 × 0.22, 0.75) + min(弱关键字数 × 0.06, 0.18) + 特征补正
```

| 项 | 说明 |
|---|---|
| **强关键字** (`keywords`) | 一命中就是强证据。如发票的「发票代码」「价税合计」 |
| **弱关键字** (`weak`) | 辅助证据，单个权重低。如「金额」「日期」 |
| **排除词** (`veto`) | 命中则**整类跳过**。用于区分易混淆类 |
| **特征补正** | 图像客观特征带来的加减分，见下表 |

## 二、图像客观特征

| 特征 | 含义 | 典型用途 |
|---|---|---|
| `color_richness` | 唯一颜色数 / 总像素，0~1 | >0.25 且无文字 → 照片 |
| `mean_saturation` | 平均饱和度 0~1 | 高饱和 → 天然照片；低饱和 → 扫描件 |
| `is_grayscale_like` | 饱和度 <0.06 视为近灰度 | 扫描文档、黑白复印 |
| `edge_uniformity` | 边缘区域是否接近纯色，0~1 | 高值 → 白底文档/截图 |
| `dark_ratio` | 暗像素占比，近似文字覆盖率 | 判断文字密度 |
| `aspect_ratio` | 宽/高 | 1.4~1.8 像证件；<0.85 像手机截图 |
| `mean_brightness` / `contrast_std` | 亮度、对比度 | 辅助判断拍摄质量 |

特征补正规则（内置）：

| 分类 | 触发条件 | 加分 |
|---|---|---|
| 照片 | 无文字 + 色彩丰富度 >0.25 | 直接置 0.8 |
| 照片 | 无文字 + 饱和度 >0.2 | 0.55 |
| 表格/单据 | 背景规整 >0.7 且数字占比 >0.15 | +0.15 |
| 聊天/网页截图 | 竖长构图(<0.85) + 背景规整 >0.6 | +0.12 |
| 证件/证照 | 长宽比 1.4~1.8 + 背景规整 >0.6 | +0.10 |

## 三、自定义规则格式

### 完整形式

```json
{
  "类名": {
    "keywords": ["强特征词"],
    "weak":     ["弱特征词"],
    "veto":     ["命中则排除"]
  }
}
```

### 简写形式（只有强关键字时）

```json
{
  "类名": ["关键字1", "关键字2"]
}
```

## 四、调优实战建议

### 1. 关键字要选「这一类必有、别类必无」的词

| 场景 | ❌ 不好的关键字 | ✅ 好的关键字 |
|---|---|---|
| 发票 | 「金额」（合同也有） | 「发票代码」「价税合计」 |
| 合同 | 「日期」（到处都有） | 「甲方」「违约责任」 |
| 简历 | 「姓名」（到处都有） | 「工作经历」「教育背景」「求职意向」 |

### 2. 善用 veto 处理易混淆类

发票和合同都可能出现「金额」「日期」，但只有合同有「甲方/乙方」：

```json
"发票": { "keywords": ["发票代码","价税合计"], "veto": ["甲方","乙方"] },
"合同": { "keywords": ["甲方","乙方","违约"], "veto": ["发票代码"] }
```

### 3. 置信度阈值怎么定

| 阈值 | 效果 | 适用 |
|---|---|---|
| 0.2~0.3 | 宽松，多命中、误报多 | 初筛，宁多勿漏 |
| 0.4~0.5 | 平衡（推荐起步） | 一般归档 |
| 0.6+ | 严格，只保留高置信 | 自动流转，宁缺勿滥 |

命令行：`--threshold 0.4`

### 4. 分类不准时的排查顺序

1. **先看 OCR 文本**：`ocr.py 图片 --json > o.json`，确认关键字是否真被识别出来了（识别错字 → 改关键字或提高图片质量）
2. **再看判据输出**：分类结果里的 `evidence` 会告诉你是哪个关键字命中的
3. **检查 veto 冲突**：某类总是漏判，可能被别类的 veto 拦掉了
4. **调整阈值**：置信度徘徊在阈值边缘时，适当下调

## 五、已知能力边界

| 能力 | 状态 |
|---|---|
| 印刷体中文/英文识别 | ✅ 良好（RapidOCR PP-OCRv3） |
| 简单表格表头分列 | ✅ 良好 |
| 复杂表格（合并单元格、无线框） | ⚠️ 可能错位，建议人工复核 |
| 手写体识别 | ⚠️ 有限，准确率明显低于印刷体 |
| 图形/图表内在含义理解 | ❌ 不支持（纯本地方案的能力边界） |
| 图片语义理解（这是猫/这是情绪） | ❌ 不支持 |

> **关于语义理解**：本 skill 走纯本地 OCR 路线，能读「字」不能读「画」。
> 若需语义级理解，需接入多模态模型，但那会引入网络依赖，与离线要求冲突。
