# Agent 交付与运维

> 本 skill 为「行业通用实践」，非《Hello-Agents》教材蒸馏产物。用于补齐 Agent 产品生命周期的**交付**环节。

## R — 原理锚点

> Agent 与传统软件的最大区别在于：它的**成本、行为、输出都是非确定的**。传统软件上线后成本固定、行为可复现；Agent 每次调用都消耗 token、每次输出都可能不同。

这段为什么重要：它决定了 Agent 交付运维的独特难点——不能照搬传统软件的「上线即结束」，必须持续管理成本、监控漂移、兜底不确定性。

> LLMOps 的核心理念：把「成本、质量、延迟」当作三个需要**持续观测与设护栏**的指标，而不是上线时一次性配置。

这段为什么重要：Agent 的护栏（成本上限、质量门控、内容安全）是运行期资产，不是开发期交付物，必须在交付阶段显式建立。

> 「上线即巅峰」是 Agent 产品最常见的死亡方式：没有评估→反馈→迭代的闭环，模型一升级、数据一漂移，产品就悄悄退化。

这段为什么重要：交付不是终点，交付时建立的可观测性与评估闭环，决定了产品能否持续存活。

## I — 骨架

交付运维五支柱，缺一不可：

### 1. 部署拓扑

| 场景 | 方案 |
|---|---|
| 内部工具 / 原型 | 单机进程 + 本地 MCP（Stdio/Memory） |
| 团队共享 / 生产 | 服务化（FastAPI/HTTP）+ 远程 MCP（HTTP/SSE） |
| 高并发 / 多节点 | 无状态服务 + 消息队列 + 负载均衡 |
| 需隔离的多租户 | 按 `user_id` / `namespace` 隔离记忆与检索（对应记忆隔离） |

**部署即配置三件套**：环境变量外置（密钥不进代码）、依赖锁定（版本 pin）、配置分层（开发/生产分离）。

### 2. 成本护栏（Agent 独有，最关键）

- **单次上限**：`max_tokens` / `max_steps` / `max_tool_iterations` 设安全阀（防死循环烧钱，同《Hello-Agents》判据）。
- **预算上限**：日/月 token 预算，超限降级或告警。
- **速率限制**：API 调用加延迟（生成类正文 2–3 秒、脚本 3–5 秒）防限流（同评估 skill 的工程纪律）。
- **降级策略**：昂贵能力（多查询扩展、Reflection 多轮、批量生成）在预算紧张时降级为单查询/单轮。
- **成本可视化**：按任务/用户/Agent 分账，让成本可归因。

### 3. 可观测性

- **日志**：每步 Thought/Action/Observation 全量落盘，可回溯（对应 ReAct 调试五条序）。
- **Trace**：一次交互的完整调用链（提示词→工具调用→结果→最终回答），错误可定位到具体环节。
- **指标**：成功率、平均步数、平均成本、平均延迟——对应评估阶段建立的指标体系（`agent-evaluation-loop`）。
- **告警**：成功率跌破阈值、成本异常飙升、格式错误率上升时告警。

### 4. 安全与合规护栏

- **权限控制**：工具分级授权，危险操作（删文件、执行命令、发消息）需白名单/确认；MCP 工具注意「工具名冲突」与「任意工具可调」的权限缺口（《Hello-Agents》第 10 章公开缺口）。
- **输入输出校验**：执行表达式前字符白名单（如 `allowed_chars = set('0123456789+-*/(). ')`）；LLM 结构化输出「先直解、失败再修复」。
- **内容安全**：输入/输出双向审核（涉政/涉黄/敏感），AI NPC 类产品需「预算 + 缓存 + 审核」三道防线。
- **数据隐私**：敏感信息删除要彻底（向量库/图库都要清，不只删记录）；跨体通信注意端到端加密缺口。

### 5. 交付文档与验收迭代

- **交付文档清单**：产品说明、能力边界（能做什么/不能做什么）、API 文档、部署手册、运维手册、已知局限。
- **验收执行**：用需求阶段定义的 DoD（`agent-requirement-analysis`）逐项核验定量指标；给人工评估配低摩擦界面（结构化打分 + 三态标注 approved/rejected/needs_revision）。
- **迭代闭环**：评估 → 归因（分类准确率 + 下降率 + 错误分布）→ 反推改进 → 再评估。把评估接入 CI/CD 并设性能阈值防退化。

## A1 — 案例

**案例 1：AI NPC 小镇的并发成本失控（成本护栏示范）**
场景：赛博小镇里每个 NPC 的每次对话都实时调 LLM，多玩家并发时成本爆炸、延迟飙升。做法：改用「离线批量生成全部 NPC 对话 + 在线仅即时交互」的混合模式，用 `busy` 状态锁防并发重复响应，配合内容审核。可迁移教训：**成本问题往往要用「批量预生成 + 缓存」从架构上解决，而非单纯调参数**；Agent 产品的成本曲线比传统软件陡峭得多。

**案例 2：工具权限的公开缺口（安全护栏示范）**
场景：Agent 挂载了能「删除文件」「执行系统命令」的 MCP 服务。做法：交付前识别到「客户端可调用 Server 任意工具，缺少权限控制」这一协议层缺口，自行补齐工具白名单 + 危险操作二次确认。可迁移教训：**交付阶段必须假设「协议/框架的默认安全能力不完整」，主动补权限控制，不能指望上游兜底**。

**案例 3：评估闭环防退化（迭代示范）**
场景：一个智能体上线后换了底层模型，结果输出格式开始偶发不兼容。做法：交付时把评估脚本接入 CI/CD，设性能阈值门控（5 样本快测→50→全量），模型升级前先跑门控。可迁移教训：**「上线即巅峰」的根因是缺自动化门控**，把评估固化进交付流水线才能防悄悄退化。

## A2 — 触发场景

- 用户说「Agent 开发完了，怎么上线/部署」
- 用户反馈「Agent 上线后太烧钱 / 成本不可控 / 老被限流」
- 用户要求「给 Agent 加监控、日志、告警，出错能定位」
- 用户问「Agent 的权限、内容安全、数据隐私怎么保障」
- 用户要「写交付文档 / 做用户验收 / 建立持续迭代机制」

## E — 执行步骤

1. **定部署拓扑**：按并发/隔离需求选单机/服务化/多节点方案，产出部署方案 + 环境配置三件套。
2. **设成本护栏**：配置安全阀、预算上限、速率限制、降级策略，产出成本控制清单。
3. **建可观测性**：接入日志/Trace/指标/告警，产出监控方案与告警阈值表。
4. **补安全护栏**：做工具权限分级、输入输出校验、内容审核、隐私删除方案，产出安全清单。
5. **交付与验收**：写交付文档清单，按 DoD 逐项验收，产出验收报告。
6. **建迭代闭环**：把评估接入 CI/CD + 设性能门控，产出持续迭代机制。

## B — 边界与失效条件

**不该用本 skill 的情况**：产品还在需求分析/设计/开发阶段（分别走 `agent-requirement-analysis`、设计类 skill）；或只是「跑一次性的 Agent 脚本」，不需要交付运维。

**已知失效模式**：
1. **照搬传统 DevOps**：忽略了成本、行为、输出的非确定性，上线后成本失控、行为漂移无感知。
2. **护栏缺失**：没设安全阀/预算上限，一次死循环或恶意输入就烧穿预算。
3. **可观测性缺失**：Agent 出错只能靠「用户截图」，无法定位到具体环节。
4. **安全缺口不补**：默认协议/框架安全能力完整，危险操作无权限控制。
5. **上线即巅峰**：没建评估闭环，模型/数据一漂移就悄悄退化。

**成本代价**：护栏与可观测性有前置开发成本，但远低于「一次事故烧穿的预算」或「悄悄退化导致的用户流失」。小工具/内部原型可裁剪五支柱，只保留安全阀 + 日志即可，不必全上。
